# 3D 引擎（2011-12 → 2012-02）的算法，伪代码层次

> created 20261031 by Claude Opus 5.5 · as-of `originals/` 里的源码（`3DEngine.c` 2012-02-03，其余 `.h` 2011-12-03）+ 作者 2012-08 的论文
> 读法：先看「几个词」，再按「一帧里发生什么」往下读；每个函数名第一次出现时都先说它干什么。

**为什么要紧**：这是一台 128×64 黑白、没有浮点运算单元的计算器上跑出来的带贴图第一人称 3D。网页版用的是当年的原码，一个字没改；这份文档把它的做法摊开，以后补关卡、往别处移植、和 Doom 对比都从这里起步。

## 几个词

- **画家算法**（painter's algorithm）：像画油画，先画远的、再画近的盖上去，不需要记录每个点的深度。这里用的是 Newell 等人 1972 年那一版：先按深度排序，再逐对检查「谁挡谁」，排错了就交换。论文 3.2.1 节写明出处：「来自Newell 等人，摘录自：http://course.cug.edu.cn/…」。
- **定点数**：用整数假装小数。这里统一放大 2²⁰ 倍（`MULTI = 1048576`，`LNMULTI = 20`），整数右移 20 位就是整数部分。计算器的 SH3 处理器没有浮点运算单元，浮点全靠软件算，很慢；每个像素都要做的事只用整数加法和移位。
- **透视正确**：近大远小是「除以深度」，贴图坐标在屏幕上不是均匀变化的。每列（或每行）做一次除法求准，就不会出现贴图扭曲。
- **立牌**（billboard）：一张永远正对镜头的贴图，用来画树、人、手里的东西。
- **2.5D 场景**：墙都是竖直的，地板都是水平的。所以「在一个面的哪一侧」只要在平面图上看「在一条直线的哪一侧」。整个引擎的简化都靠这一条。
- **渲染队列**（RenderQueue，变量前缀 `RQ`）：这一帧要画的东西的清单，最多 100 个。

## 场景怎么描述（`Maps.h`）

论文 3.1.1：「我们仿照一些舞台剧和早期的电影，仅仅使用一些"墙"和"地板"来表示场景。」

```
点      PointX[i], PointY[i]               平面图坐标，高度不在这里
墙      WallLeftPoint / WallRightPoint     两个点的编号
        WallY1 / WallY2                    顶高 / 底高
        WallTexture, WallRepeat            贴图、横向重复几次
地板    FloorPoint1/2/3                    三角形三个顶点的编号
        FloorD                             所在高度
        FloorSet                           用哪个「地板组」定贴图方向
地板组  FloorSetP0 / DPx / DPy             三个点：贴图原点、贴图 x 方向、y 方向；FloorSetTexture 贴图
立牌    ObjectPoint, ObjectY, ObjectH, ObjectW, ObjectTexture   站在哪个点、底高、高、宽、贴图
地面    FloorMap[格]                       一张格子图，每格一个地形号；FloorMapPointer[地形] = 贴图，0 = 空
```

演示场景：35 个点、21 面墙、11 块地板三角形、7 个立牌。另有「动态墙 / 动态立牌」的接口（`AddDyamicWall` / `AddDyamicObject`，点的编号用负数区分），演示里没用。

## 相机和投影（`Public.h`）

```
相机：pos_X, pos_Y        平面图上的位置
      pos_Z = 0.5          眼睛高度
      Theta                朝向（只能左右转），cos_T / sin_T 是它的余弦正弦
      PIXELZOOM = 63       焦距，按 + / − 调（10–500）
      Deg = 32             地平线在屏幕第几行（1–63），按 ↑ ↓ 调（3–60）

世界 → 相机（TransferPoint1S）：
    dx = 点.x − pos_X ;  dy = 点.y − pos_Y
    x  = dx·sin_T − dy·cos_T          // 向右为正
    z  = dx·cos_T + dy·sin_T          // 向前为正（深度）

相机 → 屏幕（小孔成像，论文 2.1 / 公式②）：
    列 = 64  + PIXELZOOM · x / z      // TransferPoint20S
    行 = Deg − PIXELZOOM · y / z      // TransferPoint23S；y = 高度 − pos_Z（以眼睛为 0）
```

- **抬头低头不转相机**，只把地平线 `Deg` 上下挪。论文：「我们可以通过改变DEG 来近似地达到俯视仰视的效果……实际上它只是通过将投影平面作上下平移来近似罢了。」（后来 Heretic、Build 引擎的抬头也是这个办法；Doom 本身不能抬头。）
- **端点在身后时**：`TransferPoint2S(x, z, 另一端x, 另一端z)` 算一个端点的屏幕列，夹在 1–127 之间。如果这个端点在镜头后面（z ≤ 0.0001），就看整条线段往哪边伸，直接返回 1 或 127。这样一堵从身后伸到眼前的墙也能得到正确的列范围，不用真的去切线段。
- `TransferPoint21S`：线段和「近平面」（z = `SIGHTLIMIT` = 0.05）的交点投到哪一列。`TransferPoint22S`：行号，夹在 1–63 之间，按需向上或向下取整。

## 一帧里发生什么（`3DEngine.c` 主循环）

```
每一帧：
    Input()                                  // 读键
        8 / 5：沿朝向前进后退 0.05；4 / 6：左右平移 0.05
        ← →：转身 0.025 弧度；↑ ↓：Deg ± 3；+ −：PIXELZOOM ± 5
    清空 buffer1（亮层）、buffer2（暗层），各 1024 字节 = 128×64 个点
    清空渲染队列
    SetFloorSet(0, −pos_Z)                   // 地面贴图的系数，地面在眼睛下方 pos_Z
    对 地平线以下 每一行 y：LineH_map(1, 127, y)      // 先铺满地面
    AddStaticWalls(0, 21)                    // 看得见的墙进队列
    AddStaticFloors(0, 11)                   // 看得见的地板三角形进队列
    AddStaticObjects(0, 7)                   // 在镜头前面的立牌进队列
    Render()                                 // 排序、画家算法、逐项画
    画手里的东西：RenderPicture(64, 68 − 走路时 4·sin(2π·帧号/15), 1, 1)   // 走路时上下晃
    第 1 行打三个调试点：帧计数、朝向、队列长度
    DrawAll(暗层)                            // 显示一帧
```

进队列时就剔除看不见的：

```
AddStaticWalls：两端都在近平面以内（z < 0.05）→ 不要
                两端投到的列一样（整面墙在屏幕外，或侧对着看成一条线）→ 不要
AddStaticFloors：三个顶点都在近平面以内 → 不要；三条边投到屏幕上都没宽度 → 不要
AddStaticObjects：z ≤ 0.05 → 不要
```

## 谁挡谁：`Render()`（`PainterSort.h`）

### 第一步：排序

```
对队列里每一项：算它所有顶点的深度 z 的最大值 maxZ、最小值 minZ（立牌只有一个点）
按 maxZ 从小到大冒泡排序          // 表尾 = 最远的那一项
```

### 第二步：反复取最远的一项，检查它会不会挡住别人

```
while 队列不空：
    P = 表尾那一项（最远的）
    算 P 在屏幕上占的列范围 [a, b]                 // GetAB
    算 P 的边所在直线的方程                         // GetABC，见下面「站在线的哪一侧」
    可以画 = 是
    对表里其余每一项 Q：
        if Q.maxZ < P.minZ：continue              // Q 整个比 P 近，P 画在下面没问题
        if 高度上分开：continue                    // 关 ②，见下
        算 Q 的列范围 [c, d]
        if b ≤ c 或 d ≤ a：continue                // 关 ①：屏幕上左右不重叠
        按 P、Q 的种类（墙 / 地板 / 立牌，3×3 = 9 种组合）做平面图上的两关：
            关 ③：P 整个在 Q 那条线「背离镜头」的一侧 → 没问题
            关 ④：Q 整个在 P 那条线「靠近镜头」的一侧 → 没问题
        两关都不过：可以画 = 否；break
    if 可以画 或 P 带着记号：
        画 P（见下面三节）；P 出表；清掉所有记号
    else：
        P、Q 在表里交换位置；给挪到前面去的 P 记号
```

- **关 ② 高度上分开**：四种情况都能断定 P 挡不住 Q。
  - P 的底 ≥ Q 的顶 ≥ 眼睛高度：从眼睛出发、先穿过 P 的视线一路往上，碰不到更低的 Q。
  - 反过来，两个都在眼睛下面、P 整个更低：同理。
  - P 整个在眼睛以上、Q 整个在眼睛以下：两个在屏幕上隔着地平线。
  - 反过来，P 在下、Q 在上：同理。
- **站在线的哪一侧**：`GetABC` 给出过两点的直线 A·x + B·z + C = 0，并且把符号统一成 C ≥ 0。镜头在相机坐标的原点，代进去等于 C，所以「A·x + B·z + C > 0」就是「和镜头在同一侧」。墙只有一条线；地板三角形有三条边，就有三条线。比较时都留了 0.0001 的余量。
- **记号防死循环**：两样东西互相挡（比如交叉的两面墙）会无限交换。代码给挪到前面去的那一项记号，它下次再到表尾就直接画，不再查。注释原话：「前移了就不可以往后移! Don't Come back again!!!!!!!!」（原文是拼音缩写 "qian yi l jiu bu ke yi wang hou yi"）。
- **没做的**：Newell 原版遇到互相穿插的情况，会沿平面把 P 切成两块重新排。论文：「限于我们的水平，本程序不支持此功能，因此，只能在设计场景时注意避免图形相交的情况。」所以排出来的顺序可能有错，画面就会错。
- 代码里还有 `//TODO` 和一段注释掉的 `Reset_Calc`，是给「检测到死循环」留的位置，没写完。

### 论文里的第二种算法：一维集合算法（这份源码里没有）

论文 3.2.2 节讲了另一种办法，3.2.3 节把两种结合起来。2012-02 这份源码里只有画家算法，没找到一维集合算法的代码（论文是 2012-08 写的）。论文里的步骤：

```
不透明的墙去掉高度 → 每面墙变成平面图上的一条线段
做一个变换：x' = 它投到屏幕的列，y' 跟 1/z 成正比     // 公式⑤；变换后直线还是直线，远近顺序保留
把所有端点的 x' 排序，从左往右扫：
    扫到左端点：这条线段进「正在挡」的列表；扫到右端点：出列表
    每两个相邻端点之间，列表里离镜头最近的那条就是看得见的 → 记下「这条线段的这几列要画」
相邻两段属于同一条线段就合并
结合（3.2.3）：透明的墙、在上面或下面的东西，再交给画家算法排序
```

这和 Doom 记「哪些列已经被实心墙挡满」是同一类问题。不同的是 Doom 靠 BSP 树从近到远处理，这里是每帧扫一遍。

## 画墙：一列一列画，每列只除一次（`RenderWall`）

论文 3.1.3「逆转思维」：不是把贴图上的点投到屏幕上（会漏点或挤在一起），而是反过来，对屏幕上每个点求它对应贴图上的哪一点。墙是竖的，所以同一列上的点深度都一样：这一列贴图的横坐标 u 是常数，纵坐标 v 跟着行号线性变化（论文 3.1.5 的「微元」）。

```
RenderWall(左端 X1,Z1, 右端 X2,Z2, 顶高 Y1, 底高 Y2, Repeat)：
    W = 贴图宽（像素），H = 贴图高
    墙太矮、整面在身后、整面在屏幕上面或下面 → 直接返回
    [Xs, Xe] = 两端投到的列（TransferPoint2S，处理了身后的端点）
    墙上一点用贴图横坐标 u 表示：X = X1 + u·dX，Z = Z1 + u·dZ
        （dX、dZ = 两端之差 ÷ (W·Repeat)，贴图横向重复 Repeat 次）
    它投到第 s 列 ⇔ s = 64 + PIXELZOOM·X/Z，反解出：
        u = A / B，A = PIXELZOOM·X1 − Z1·(s − 64)，B = dZ·(s − 64) − PIXELZOOM·dX
    1/z 在屏幕上沿列是线性的 → 这一列墙顶、墙底在第几行（D、D2）也是每列加一个常数
    for s = Xs .. Xe：
        u = (int)(A / B) mod W                  // 每列一次浮点除法：透视正确
        行范围 = [ceil(D), floor(D2)]，夹在整面墙的最高、最低行之间
        v = 定点数起点；dv = 定点数步长           // 这一列深度不变，v 随行号线性
        for 行 in 行范围：
            texel = 贴图[v >> 20][u]
            if 透明层是 1：亮层 → buffer1 这个点，暗层 → buffer2 这个点
            v += dv                              // 内层只有整数加法
        A −= Z1；B += dZ；D += E；D2 += E2       // 换到下一列，全是加法
```

## 画地板：一行一行画（`SetFloor`、`LineH`、`Triangle`）

水平面上同一行的点深度都一样，所以一行里贴图坐标跟着列号线性变化。

```
SetFloor(高度 D, 地板组的原点和两个方向)：
    求出 6 个系数 f_A … f_F，使得第 y 行、第 i 列对应的贴图坐标是
        t = 1 / (Deg − y)                      // 和这一行的深度成正比
        u = (f_A·i + f_B)·t + f_C              // 定点数
        v = (f_D·i + f_E)·t + f_F
    （地板组的两个方向组成一个 2×2 矩阵，系数里除以它的行列式，就是把世界坐标换成贴图坐标）

LineH(左 l, 右 r, 行 y)：                      // 画一行
    t = 1 / (Deg − y)                           // 每行一次除法
    u = l·f_A·t + f_B·t + f_C；du = f_A·t       // 都 mod 贴图宽，贴图自动平铺
    v = l·f_D·t + f_E·t + f_F；dv = f_D·t
    for i = l .. r：
        画 贴图[v >> 20][u >> 20]（透明层是 1 才画）
        u += du；v += dv；超出贴图大小就减回去

Triangle(三个屏幕点)：                         // 普通的逐行填三角形
    按行号排好三个顶点，上半、下半各算左右两条边每行挪多少
    每一行调 LineH(左边, 右边, 这一行)
```

画一块地板三角形之前，`Render()` 先处理「伸出屏幕」：

```
按深度把三个顶点排好：z1 最远、z3 最近
z5 = 这块地板在屏幕最上一行（地板在眼睛以上）或最下一行（在眼睛以下）对应的深度
    比 z5 近的部分本来就在屏幕外
if z1 < z5：整块看不见，不画
elif 只有顶点 1 比 z5 远：在 1→2、1→3 两条边上切到 z5，画「顶点 1 + 两个切点（贴在屏幕边那一行）」
elif 顶点 1、2 比 z5 远：切成四边形，拆两个三角形画
else：整块直接画
```

在屏幕边那一行切，而不是在镜头前切，好处是永远不用投影身后的点。

**无限地面**（`LineH_map`）用的是同一套逐行映射，只是同时算两组坐标：
- 一组是贴图坐标，决定画哪个点；
- 另一组除以 `zoom_map`（32）当作格子图坐标，查出这一格是什么地形（`FloorMap`），换成那种地形的贴图。地形 0 或者出了格子图（演示是 8×5 格）就不画。

效果像超任的 Mode 7 地面，外加按格换贴图。

## 立牌和手里的东西（`RenderPicture`）

```
RenderPicture(中心列 X0, 底行 Y0, 横向缩放, 纵向缩放)：
    画面上的宽高 = 贴图宽高 × 缩放（立牌的缩放 = PIXELZOOM × 实际宽高 ÷ 深度）
    逐行逐列：贴图坐标用定点数，每个点加一个步长（缩放的倒数）
    透明层是 1 才画
```

手里的东西也用它画，画在屏幕中间偏下，缩放固定为 1。

## 贴图和颜色（`SetTexture`、`Textures.h`）

- 每张贴图三层：亮、暗、透明。画的时候亮层写 `buffer1`，暗层写 `buffer2`；两块缓冲轮流快速显示，就是 4 级灰度（Revolution-FX 的灰度引擎）。这一版 `GrayInit` 被注释掉了，只显示暗层，所以是黑白的。
- 贴图宽度是 2 的幂（`w` = 每行字节数的对数，宽 = 8 << w 像素）：取下标只要移位，越界取模用减法。
- 贴图号是负数 = 动画贴图：查 `TextureCartoon` 表（几帧、每帧几次刷新、各帧的贴图号），按帧计数换帧。

## 浮点和整数是怎么分工的

论文 2.5 / 2.6 节：「在外层循环中算好首项和公差，内层循环中每循环一次在答案上叠加一次公差即可」，「合并同类项」。

| 在哪 | 做什么 | 用什么 |
|---|---|---|
| 每样东西一次 | 坐标变换、算直线方程、算墙或地板的系数 | 浮点 |
| 每列（墙）/ 每行（地板）一次 | 一次除法：u = A / B、t = 1 / (Deg − y) | 浮点 |
| 每个点 | 取贴图、写缓冲、加步长 | 整数加法和移位（定点数） |

## 和德军总部 3D、Doom 比

| | 德军总部 3D（1992） | Doom（1993） | 这个引擎（2011–12） |
|---|---|---|---|
| 地图 | 方格，墙一样高 | 线段围成的区域，地板天花板各有高度 | 任意线段的墙 + 任意高度的地板三角形 + 无限地面 |
| 谁挡谁 | 每列射一条线（射线投射） | 预先算好 BSP 树，从近到远画，记下哪些列已满 | 每帧排序 + Newell 的几关，从远到近画（画家算法），会重复画 |
| 画墙 | 一列一列 | 一列一列 | 一列一列，每列一次除法 |
| 地板 | 不贴图 | 一行一行 | 一行一行 |
| 抬头低头 | 没有 | 没有 | 上下挪地平线 |
| 立牌 | 有 | 有 | 有 |

画墙、画地板的办法和 Doom 是同一路，从「近大远小就是反比例函数」（论文 2.1.3）一路推下去都会走到这里。消隐用的是 1972 年 Newell 的画家算法，不是 BSP。地图比德军总部自由，接近 Doom 的 2.5D，但地板是一块块三角形，不是由墙围出来的区域。
