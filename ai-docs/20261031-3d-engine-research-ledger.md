## R1 任意斜三角形：每次画一条深度相等的斜线

> 接着开发呗。其实我当时已经有任意三角形的构想了，现在我也回忆起来了。这个3dengine专门开一个科研记账。和2012年分开。
> 就是我在想的是每次画一条z=常数的斜线，然后用好的光栅化算法保证每次画的线中间不要有洞。……到时候交付物我希望是一个按照当时的knowledge cutoff的proof和伪代码。然后有任意斜的三角形之后摄像机就可以随意了，然后wishlist渲染实验室可以接图形引擎2026版。

- **题目**：2012 年的引擎只画得了竖直的墙和水平的地板，因为竖直的面「同一列深度相同」、水平的面「同一行深度相同」，一列或一行里贴图坐标随位置均匀变化，只要做加法。作者的构想是推广到任意斜面：面上深度相同的点连成一条线，沿这条线画，贴图坐标也是均匀变化的。
- **Claude 的读法（没证）**：
  - 斜面上「深度 = 某个常数」的点，是这个面和一个与屏幕平行的平面的交线，是一条直线，投到屏幕上还是直线；沿它深度不变，所以屏幕到贴图是一次函数，每条线只做一次除法。
  - 同一个面上所有这样的线方向都相同，而且都和屏幕平行，所以投到屏幕上**互相平行**（斜率一样，没有灭点）。于是整个三角形可以用一族平行斜线扫满。
  - 「中间不要有洞」：一族平行斜线沿短的那个方向每次挪一个像素，每条线用**同一个点阵模板**（同一套取整），相邻两条正好拼满、不重不漏。这是要证的那一条。
- **交付物（作者定的）**：一份证明 + 伪代码，按 2012 年的知识写：高中数学（相似三角形、直线方程、一次函数递推），不用矩阵和线性代数。知识范围由作者到时候给——Shader 实验室 README 10-27 那条同一件事：「只用 user 高中知识范围内的数学和做法，范围由 user 到时候给」「斜的面怎么切是 user 当年想过的一处」。
- **当年的知识边界**（作者 10-31「历史记账」）：「微元法就是贴皮的微积分，只是dx*dy会fomo不知道该丢罢了」「但是线性代数我是全量不会」。论文 3.1.5 的「微元」就是这个。
- **作者对推法的判断**（同日，没改交付物）：「不过三角形的算法我以一个负责任的成年人判断不用线性代数，用cpho的推法会非常痛苦。而且可能会miss一些合并优化空间」。
- **作者的理念**（同日）：「可能是因为我想省掉稀疏矩阵的几个0所以觉得展开形式才更接近物理和算力本源吧！线性代数是用空间来换复杂度的，哈哈哈！」——2012 年的代码确实没有一个矩阵：只能左右转，变换写成 2×2 的展开式；墙竖、地板平，「在面的哪一侧」退化成平面图上的直线方程。
- **之后**：有了任意斜三角形，相机就能随意转（现在只能左右转、抬头低头是上下挪地平线）。Shader 实验室的 wishlist 接图形引擎 2026 版。
- 状态：开题，没做。

## R2 当年代码的优化空间

> 我还以为至少有几个float之类的常识错误可以优化。如果让你或者fable写咱们的优化空间还有多大。分low hanging fruit和全量fable。你可以把其他几个大人写的doom拉下来放放参考的地方对

- 题目：同一个场景、同一台机器，顺手改（不换算法）能快多少，换算法全量重写能快多少；拿别人在卡西欧上写的 3D 引擎 / Doom 移植对照。
- **怎么量的**（10-31，Claude Opus 5.5）：把当年的 `.h` 原样复制到临时目录，只在函数入口和最里层循环加计数器，电脑上用 gcc 编；照主循环画一帧（不读键、不显示），开局位置原地转一圈、32 个朝向，每帧数一遍。第一帧和网页版逐点一致（只差第 1 行两个调试点），所以数的是同一套代码。
- **每帧做了多少事**（平均 / 最多）：

  | 什么 | 平均 | 最多 | 说明 |
  |---|---|---|---|
  | 待画清单 | 15 项 | 38 项 | 墙 + 地板三角形 + 立牌 |
  | 世界 → 相机的坐标变换 | 414 次 | 1,246 次 | 场景只有 35 个点：两两比较时同一个点反复重算 |
  | 屏幕列范围 / 直线方程 | 77 / 30 次 | 286 / 92 次 | 同上，每次比较现算 |
  | 两两比较 | 232 次 | 898 次 | 真正比到要交换的 2 次 |
  | 画墙的点 | 4,804 | 6,540 | 每列 1 次浮点除法，共 235 列 |
  | 画地板三角形的点 | 1,752 | 4,785 | |
  | 铺地面的点 | 3,937 | 3,937 | **真写进缓冲的只有 37 个**：格子图大半是空地形，白算 |
  | 画立牌 + 手里的东西的点 | 6,335 | 9,737 | 真写 2,396 个；手里的东西缩放永远是 1，也逐点缩放 |

- **结论（Claude 的读法）**：
  - 核心算法当年已经对了：每列 / 每行一次除法（透视正确），最里层只有整数加法和移位。拿检疫桶 `casio-3d-refs` 里别人的引擎比：多数用 double 做矩阵、只平涂不贴图；贴图做得最全的 VIMS3D（2026）在透视正确模式下**每个点**一次除法。
  - 浪费在「胶水」上。**顺手改（low hanging fruit，不换算法）**：
    1. 每帧每个点只变换一次（414 → 35），每一项的屏幕列范围和直线方程也只算一次存起来。
    2. 铺地面只扫有地形的那几格投到屏幕上的范围（3,937 → 几十）。
    3. 手里的东西换成排好的小图按字节贴，一次 8 个点（6,335 次逐点缩放 → 几百次字节操作）。
    4. 灰度关着时不写亮层：现在每个写出的点读三层贴图、写两块缓冲，显示只用暗层。
    5. 浮点常量带上 `f`：`0.05`、`0.0001`、`64.5` 在 C 里是 double，比较和加法会升成双精度软件运算（要看当年的编译选项，没核）。
    6. 缓冲拷贝逐字节 → memcpy；`Render()` 每帧重算 `sinf` / `cosf`。
    估计快 1.5–3 倍（没量）。
  - **全量重写（Fable 级，换算法）**：
    1. 浮点归零：坐标变换、每列每行那次除法全换定点数 + 倒数表。
    2. 从近到远画 + 屏幕列覆盖表（论文的一维集合算法、Doom 记「哪些列已满」同一类）：墙的每个点只画一次，被挡住的不算；每帧的两两比较换成关卡预处理（BSP 或分区）。
    3. 直接写显存；墙按列画进按列存的缓冲，最后转一次；立牌预缩放几档按字节贴。
    4. 可选：最里层写汇编。
    估计快 4–10 倍（更没量）。省出来的时间可以花在 R1 的任意斜三角形或灰度上。
- 状态：计数是量的，倍数是估计。真要量倍数，用 R4 的工具链编出来，在真机或指令模拟器上计时。

## R3 1-Bit Jam：白面黑线的线框 + 背面消隐

> 冲1bit jam的话还有一个思路是sunset 图形引擎，做一个渲染实验室里面的带背面消隐的线框，这个9750gii接得住吗，会不会反而更快。你帮我前期科研一下。是不是非得要深度缓冲。

> 最好是好看的那种不是全量线框的，catsup里面有更新版的。但是只要效果一致就行，不一定要用他们的算法

- **要的效果** = CatsUp 的线稿（CatsUp `ai-docs/20261030-silhouette-outlines.md`）：白色的面、黑色的线，被挡住的线不画；硬边看得见就画；软边只在它正好是外轮廓时画（两侧的面一个朝镜头、一个背镜头）；外轮廓可以加粗；两个物件穿插的交线不画（SketchUp 同款）。Shader 实验室的「卡西欧 · 线稿」是同一路的 1-bit 版本。
- **结论（Claude 的推理，没写代码、没量）**：
  - **不用深度缓冲。**
    - 面朝不朝镜头 = 投到屏幕上的三个点是顺时针还是逆时针（整数叉乘的正负）；背着的面不画。
    - 哪条边画：硬边 = 两侧至少一面朝镜头；软边 = 两侧一正一反（就是外轮廓，和 CatsUp 同一条判法）；开口的边 = 总画。
    - 被挡的线：从远到近，每个面先涂白、再描它要画的边。近的面涂白时自然盖掉后面的线——「白面黑线」本身就是这么画的。
    - 远近顺序：一个物件里凸的部分只靠背面剔除就对；多个物件按物件排序；面互相穿插、排不出顺序的，设计关卡时避开（论文当年也这么做），或者退回深度缓冲。
  - **深度缓冲放得下，但没必要**：16 位 × 128 × 64 = 16 KB；卡西欧 SDK 文档写的是全局变量最多 8 KB、堆 48 KB（VIMS3D 在老机型上就 malloc 了 32 KB 当深度缓冲）；每个点都要算深度、比深度，更慢；交线本来就不画。
  - **小屏要注意的**（Shader 实验室的「卡西欧 · 线稿」也这么处理）：投影后很小的面不描边，不然糊成一团；外轮廓 2 像素、内部硬边 1 像素，到时候调。
  - **快不快（估计）**：涂白是整字节清零，一次 8 个点；画线逐点。几十个面的场景每帧大约几万个处理器周期，当年的贴图引擎每帧 110 毫秒（约 320 万周期），快一个数量级以上，帧率会先被液晶刷新卡住。
  - **验证**：同一个模型，CatsUp 线稿渲成 128×64 和计算器出图逐点对比（像塔防截图那样对拍）。
- 状态：前期调研完，没写代码。

> 有开源的sdk当然要用，你就可以验证了。然后官方的我onedrive里面应该有备份。不过我估计你更喜欢开源的

- 定了：用开源的 fxSDK（gint）编真机 G1A；卡西欧官方 SDK 作者那边有备份，需要时再拿。魔塔「只带用到的字」那条验证（`wishlist.md`）用同一套。
