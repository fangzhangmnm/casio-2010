# 网页版计算器：2026 年的设计

> created 20261031 by Claude Opus 5.5 · as-of 2026-10-31（index.html 910 KB，12 个入口；§11 图形屏同日加）
> 2026-10-31 吃书重组后，本文住在 casio-2010 家族的 `20261030 卡西欧网页模拟器` 子仓（公用工具链）；原件在各作品子仓、2026 版在各自的 2026 子仓，文中路径按重组后的写（相对本仓）。

这份写 2026 年做的东西是怎么想、怎么搭的：模拟器、两种页面模式、触屏和重力感应、2026 版的接口。当年的程序本身（各作品子仓的 `originals/`）一个字节不改，这里不讲它们的历史。

## 1. 两种程序，两条路

| | 卡西欧 BASIC（G1M） | C 写的 Add-in（G1A） |
|---|---|---|
| 程序 | 贪吃蛇、21 点、扫雷、三国杀简版、塔防（1.0 / 1.1） | 魔塔、Doodle Jump、3D 引擎 |
| 怎么跑 | 页面里一个 JS 写的 BASIC 解释器，打开时现场解码 G1M 原件 | 当年的 C 源码 + `fxsdk/`（卡西欧 SDK 的替身）用 Emscripten 编成 WebAssembly |
| 原件在哪 | 各 BASIC 子仓的 `originals/*.G1M`，原样内嵌进页面 | 各作品子仓 `originals/` 的源码，一个字不改；当年和 C 库撞名的函数（魔塔的 `getpid` = 取图块编号）编译时用 `-D` 改名 |

解释器只实现这几个程序用到的指令；没实现的指令照真机报 `Syntax ERROR`。图形屏见 §11。

## 2. 构建流程

> 2026-10-31 补（Claude Opus 5.5）：`build.py` 除了合集计算器 `index.html`，还出 `play/<短名>.html`（每个游戏一页，只带这一个程序和它的 wasm，`AUTORUN = 0` 打开就跑；网址末尾 `#info` 同时弹出说明）和 `site/index.html`（1-bit 液晶风格的合集页：英文数字用卡西欧 5×7 字、中文用魔塔的 HZK12 只带用到的字，排版照魔塔 printf12）。魔塔 2026 单独一页时自己带中文字库。作者 10-31：「我建议是不同游戏每个一个网页？这样我可以分享单个游戏。然后每个网页都优先是点开能玩」「我觉得没必要要那个计算器内部导航，反而麻烦」「一个能玩的游戏，一个源码，一个你写的啰啰嗦嗦的介绍，每个展位三个东西就行了，游戏能玩是第一位的」。


```
../<作品子仓>/originals/（当年的字节）──┐
../<2026 子仓>/（2026 版源码、补丁）──┼─ build_g1a.py ── emcc ──> dist/g1a/<名字>.js（wasm 内嵌，不进 git）
```

- 魔塔 2026 版不另存源码：`build_g1a.py` 编它时把 `../20120703 魔塔/originals/src/` 复制一份，只换 `../20261031 魔塔 2026/fix-mapedit-hex.json` 里那 103 个字节（见 §7）。

## 3. SDK 替身（`fxsdk/`）的约定

照卡西欧《fx-9860G Libraries》手册（2007）的行为写，只写这几个游戏用到的函数。

- **显示**：VRAM 和 DD 各 1024 字节，128×64，一行 16 字节、高位在左，和真机显存同一个排法。`Bdisp_PutDisp_DD` 才把画面交给页面。
- **字**：`PrintXY` 是 6×8 一格，字形画在格子里往右 1 列的位置（对过 2012 年的截图 `ss7.bmp`）；`PrintMini` 用小字，字形从 SDK 码表第 7 页逐点采样（`casio-font-small.json`）。
- **时间**：计算器是单线程，浏览器也是。定时器（`SetTimer`）不另开线程，在 `Sleep` / `GetKey` / `IsKeyDown` 里轮询时触发；轮询每隔一会儿交还给浏览器一次（有新画面时最多 16 毫秒一次，没有时 2 毫秒忙等、15 毫秒睡）。靠 Emscripten 的 ASYNCIFY 让 C 代码「睡着」等浏览器。
- **退出**：页面上按 MENU = 像真机切到别的应用：先调程序登记的退出回调（魔塔会问存不存档），再停。`Reset_Calc`（Revolution-FX）= 回列表。
- **限速**：3D 引擎的主循环不睡觉、按帧走路，所以 `DrawAll` 按每帧至少 110 毫秒限速（论文「普通测试」原生 29.5 MHz 下 9.1 帧/秒）；页面的「速度 ×2」= 论文演示用的 2 倍超频。
- **没模拟的**：`Change_Contrast`（Doodle Jump 开局调亮、结束调回）只记下不做；灰度函数（3D 引擎里注释掉了）空实现。

## 4. 存储内存和存档

- 计算器的 `\\fls0\` 在页面里是一张表：只读文件（魔塔的中文字库 HZK12.df）跟着页面来；程序写的文件在**关闭文件那一刻**存进这个浏览器的 localStorage（键 = `gwhbob-calc.fls0/<文件名>`）。删除先只在内存里删；等程序下一次交还浏览器（或退出）时，那个文件还没被重新建出来，才从 localStorage 真删——魔塔存档是先删、再建、再写，中途出错老存档还在。
- 每个有存档的游戏，说明弹窗里有导出 / 导入：导入前核字节数（魔塔存档 = 2742 字节 = 玩家 80 + 地图 22×11×11），不对就不收；要覆盖现有存档先在弹窗里确认。
- 原样版和 2026 版共用同一份存档（见 `CLAUDE.md` 考古家规）。
- GitHub Pages 上同一个账号的所有项目共用一个域名，localStorage 是按域名分的——所以键都带 `gwhbob-calc.` 前缀，不碰别人的。

## 5. 页面：两种模式

- **真机布局**（默认）：整台 fx-9750GII，键位照真机（Getkey 码 = 键在键盘上的物理位置），颜色照实拍。按屏幕实际能看见的高度自动缩放（取窗口 / visualViewport / `100svh` 三个里最小的，地址栏、工具栏都算进去），iPhone SE 2 也一屏放下、不用滚。
- **全屏**（手游模式）：只放这个游戏这一刻用得到的键，同一个意思只放一个；键从「键帽说明」（build.py 里每个游戏每个阶段的 controls）现做。顶上一条：退出全屏、回列表、重力感应开关。
  - 电脑上顺便调浏览器的真全屏（藏地址栏）；**iPad / iPhone 上不调**：WebKit 的真全屏里手指往下一拖就退出，苹果故意的，网页拦不住（WebKit bug 264215）。贪吃蛇、3D 引擎滑屏、列表拖动都会碰到，所以那边只铺满浏览器窗口。
- **竖着拿的游戏**（Doodle Jump：真机上逆时针转 90° 拿）：真机布局模式下整台计算器跟着转；全屏模式只转液晶，配左右两个软键。
- 说明、规则、存档、调手感、源码都在每个游戏的说明弹窗里；规则和攻略默认折叠，平时只看见键位和简介（不剧透）。
- 双击不放大（`touch-action: manipulation`）；输入框用 16 号字，免得 iOS 自动放大。

## 6. 触屏和重力感应

计算器的按键是第一公民：触屏、重力感应都是叠在上面的另一层，原样版的程序看到的永远只是按键。

| 玩法（build.py 的 `bind.touch.mode`） | 谁用 | 做什么 |
|---|---|---|
| `swipe` | 贪吃蛇、3D 引擎 | 在液晶上往哪滑 = 按一下那个方向键 |
| `cell` | 扫雷 | 点格子 = 光标走过去（按几下方向键），点 = 挖，长按 = 插旗 |
| `halves` | Doodle Jump 原样版 | 按住液晶左半 / 右半 = 按住两个键 |
| `game` | Doodle Jump 2026 版 | 手指原样交给程序（`Touch_Read` / `Touch_Hit`），网页不解释 |

程序列表也能触屏：拖动按整行滚（文字模式只能整行动），点一下选中，点选中的那行就运行——像带触屏的卡西欧。

**重力感应的坐标**（三套，都是右手系）：

- iPad 机身（W3C 设备坐标）：x = 竖拿时往右，y = 往上，z = 屏幕朝外。「上」（重力反方向）用欧拉角算：`(−cosβ·sinγ, sinβ, cosβ·cosγ)`。不用 `accelerationIncludingGravity`：iOS 和别家正负号相反。
- 网页：相对机身转了 a 度，网页右 = 机身 `(cos a, −sin a, 0)`，网页上 = 机身 `(sin a, cos a, 0)`。a 按窗口横竖 + 重力在屏幕平面里朝哪边定，平放分不出时才信 `screen.orientation`——iPad 上的 Edge 横着拿时那个接口还报 0。
- 计算器：x = 液晶往右，y = 液晶往上，z = 朝外。正常摆时 = 网页右 / 上；竖着拿时计算器 x = 网页上，计算器 y = 网页左。

计算器不知道自己被装在什么网页、什么设备里——网页把读数换算到计算器坐标再交过去。2026 版的游戏只认计算器坐标。

## 7. 2026 版的接口（`fxsdk/fx2026.h`）

真机上没有，只给 2026 版用。照卡西欧库的风格：整数、出参、返回 0 = 成功 / 负数 = 失败，模块前缀 + 下划线命名。

- `int Frame_Wait(void)`：等到下一次屏幕刷新，返回距上次过了多少微秒（计算器上的时间，速度倍率算进去，最多 100000）。一帧画一次、按这个时间算位移 = 锁帧算 dt。
- `int Sensor_Read(SENSOR_DATA *)`：假想的计算器自带加速度计 + 陀螺仪，计算器坐标。`gx gy gz` 加速度计（含重力，0.001 m/s²，静止时指向「上」，平放 ≈ (0, 0, +9807)）、`ax ay az` 不含重力、`wx wy wz` 角速度（0.01°/s）、`heading`（0.01°，没有 = −1）、`age`（毫秒）。
- `int Touch_Read(TOUCH_POINT *, int max)` / `int Touch_Hit(x1, y1, x2, y2, states)`：每次 `Frame_Wait` 拍一张这一帧的触点快照，坐标是液晶上的点（和 `Bdisp_SetPoint_VRAM` 同一套）。立即模式：画控件时问 `Touch_Hit`，有手指就当场吃掉，后面的控件拿不到这根手指，不会一下点两个东西。
- `int Param_Get(int id, int def)`：页面上「调手感」的参数（整数）；`int RTC_GetTicks(void)`：当天零点起的 1/128 秒数，随机数种子用。

**Doodle Jump 2026 版**（`../20261031 Doodle Jump 2026/Doodle2026.c`，以 2013 年的 `Doodle.c` 为底）：开始画面（点一下 = 授权重力感应 + 进全屏）、跟屏幕刷新走按 dt 算位移、比例重力感应、触屏左右半屏、右上角退出钮、GAME OVER 不回列表直接重来、随机数按时间初始化。调手感的参数：

| id | 参数 | 默认 |
|---|---|---|
| 6 | 倾多少度 = 原版最快 | 1500（15°） |
| 7 | 最快封顶（原版最快的几倍） | 200%（按比例，30° 到两倍） |
| 5 | 倾角死区 | 0 |
| 1 | 原版横向最快速度 | 80 像素/秒 |
| 2 | 键盘横向加速度 | 800 像素/秒² |
| 3 | 起跳速度 | 220 像素/秒 |
| 4 | 重力 | 320 像素/秒² |

原版是 25 毫秒一跳（40 帧/秒），网页 60 帧/秒刷新，所以原样版的平台看着会一顿一顿地跳像素——那是原样，2026 版跟屏幕刷新走就没有了。

## 8. 液晶

128×64 的小图按最近邻放大，再叠一层预先画好的像素缝。颜色照实拍取色。慢液晶的残影是一个时间常数（默认 0.15 秒，估的）；每个游戏可以自己定，Doodle Jump 整屏滚动，残影拖成一片，关掉（0）。

## 9. 魔塔 2026 版：当年 MapEdit 丢掉的 103 个字节

当年用自己写的 VB 小工具 MapEdit（`../20120703 魔塔/originals/tools/MapEdit.frm`）把图片转成 C 数组，那一行是 `"0x" & Format(Hex(b), "00")`。`Hex` 给的是字符串，`Format` 想把它当数字格式化，VB 却把 `"1A"`–`"9A"` 当成时间读（`"2A"` = 凌晨 2 点），格式化出来是 `"00"`。所以这 9 种值全成了 0：53 个图块、103 个字节，图块上缺的点就是这么来的。

`../20261031 魔塔 2026/make_fix.py` 照 MapEdit 同一套算法（图块编号 0–159，第 编号÷32 行、第 编号%32 列，格距 17，每行 2 字节高位在左）从当年的原图（`../20120703 魔塔/originals/material/魔塔黑白 - 副本.bmp`）重算，只挑「原样是 0x00、原图是 0x1A–0x9A」的字节；有任何别的差异就停下。这条「VB 把 1A–9A 当时间」是从数据反推的，没真跑 VB6 验证。

`../20261031 魔塔 2026/make_ora.py` 把图块总表原像素 1:1 打包成 OpenRaster（.ora）给 WeebPaint 改；改好的图块以后也进 2026 版。

## 11. 图形屏（三国杀、塔防）

卡西欧的图形屏是另一块 128×64，和文字屏分开：最后被写的那块显示在屏幕上（Locate / 打印 / 输入 → 文字屏；Cls / Text / DrawStat / Plot … → 图形屏）。下面的约定全部从塔防 5009 帖的 6 张截图（`../20101022 塔防/originals/TDGAME-screenshot.jpg` + `TDGAME-screenshots/`，2010-10-22，真机截的 132×68 = 128×64 加一圈 2 点的边）推出来、再对回去：

| 事 | 约定 | 从哪看出来 |
|---|---|---|
| 画图区 | 液晶第 1–127 列、第 1–63 行，第 0 列、第 0 行不画 | `Horizontal` 那条线从第 1 列画到第 127 列 |
| 坐标 → 点 | `ViewWindow Xmin,Xmax,Xscale,Ymin,Ymax,Yscale`：Xmin 在第 1 列、Xmax 在第 127 列，Ymax 在第 1 行、Ymin 在第 63 行；四舍五入，**正好一半往小的取** | 塔防写 `ViewWindow 1,127,1,63,1,1`（Ymin = 63 > Ymax = 1，y 轴倒过来，坐标 = 屏幕行列）；标题的向日葵放大 1.5 倍、坐标带 .5，往大取就错开一格 |
| 画线 | Bresenham，**从终点往起点画** | 放大 4 倍的豌豆（整数坐标、斜率 1/2 的边）：从起点画，每两点一对的配对错一格 |
| DrawStat | 不清屏、不重铺背景，叠着画；xyLine 连线，Scatter 的 Square = 3×3 空心方块 | 标题上四次 DrawStat 的东西都在；对战中光标方框和子弹同时在 |
| Cls | 清空，再铺 `BG-Pict n` 的背景图 | 塔防每拍 `Cls` 后重画光标、子弹 |
| Text 行,列 | 小字（和 PrintMini 同一套），字左上角在液晶 (列, 行)；连字右边一列、下面一行一起擦白 | 「θ×」「10」的位置；塔防拿空格擦旧数字 |
| 「忙」 | 程序跑着时右上角 4×4 实心（第 124–127 列、第 0–3 行）；等输入、选单、◢ 时没有 | 所有对战截图有，选单截图没有 |
| Menu | 盖在当前画面上的窗：框第 4–124 列、第 1–63 行，右边第 125 列一道阴影；标题字在 (8, 3)，第 12 行一条分隔线；第 i 项字在 (8, 14 + 8i)，选中那项整条反白（第 7–120 列、8 行高）；字是 5×7 大字 | 任务选单、暂停选单两张 |

逐像素对拍（`__calc.target` 和截图点阵比，8192 点）：

- 标题画面：0 点不同（三次不同时刻截都是 0）。
- 任务选单（Menu 盖在标题画面上）：0 点不同。
- 暂停选单：窗口那块 0 点不同（背后是当时的随机局面，不比）。
- 三张对战截图：底下那排固定的东西（横线、三个植物图标、价钱）一致；场上的豌豆射手、太阳花、坚果、三种僵尸，按程序的坐标在棋盘格上画出来，每一个点都在截图里。冷却数字、局面是当时的，不比。

对拍时改了字体表（都照这批截图）：大字 S W a b c g h l m n o s t v 和 E590（¡）——PDF 采样时 a b c g h m n o 整体高了一行，S W l s t v 形状不对；小字补了 θ（CE，码表没有），i 的字宽 3 → 1。魔塔、3D 引擎之前对过的截图里没有这些字，不受影响。

推测、没对过真机截图的：

- `◢` 在文字屏时下一行右边写「- Disp -」；在图形屏时只停下、不写字。
- `Plot` 不带坐标：在 (X, Y) 放一个闪的十字指针，后面的 `◢` 停下时方向键一下挪一点，EXE 把位置写回 X、Y 并点上（三国杀文件里的画图试验程序用，主程序不用）。
- 速度：BASIC 按每秒 600 行估的；塔防作者原话「本游戏有点卡」，网页上也卡，可以调速度 ×2 / ×4。

另外两条跟着改的：

- 变量、列表、矩阵、字符串、Pict、图形屏是计算器的内存，跑完不清，下次跑接着用（塔防标题的 Continue 就靠这个）；刷新网页才清空。以前每次运行都清零。
- 程序跑着时 MENU 键交给程序（真机上 Getkey 读得到 48，塔防按 MENU 暂停）；中断程序回列表改成 EXIT 或 AC。
